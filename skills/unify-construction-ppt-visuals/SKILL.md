# 统一工程技术标 PPT 视觉

将每套页面当成一个有固定设计系统的系列，不要把每页当成独立海报。

## 必读资源

开始前读取：

- [style-bible.md](references/style-bible.md)：固定视觉变量、页面类型和禁用项。
- [template-registry.md](references/template-registry.md)：页面类型、固定模板 ID、组件树和坐标合同。
- [prompt-contract.md](references/prompt-contract.md)：图像生成提示词合同、连续性策略和验收表。

若要批量生成提示词，运行 `scripts/build_prompts.py`。不要手工改写脚本输出中的 `STYLE LOCK` 段。

## 工作流

### 1. 建立内容账本与语义模型

逐页记录：页码、标题、必须逐字保留的文字、关键数字、源图片、不能改变的建筑/施工事实、允许调整的版式。把文字准确性与视觉美化分开处理。

在任何排版或生成之前，先完成 `semantic_model`：

- `purpose`：用一句话说明本页要让读者理解或做出什么判断。
- `entities`：列出标段、楼层、施工区、班组、工序、日期、风险、图片等信息对象。
- `relationships`：标明包含、对应、先后、并行、对比、因果、汇总等关系。
- `reading_order`：规定读者应先看什么、再看什么、最后得到什么结论。

语义模型必须能用页面原文、数字或图示关系逐项举证。若无法解释某个元素的含义，不得为了排版方便删除、合并或重新命名；先回看源页，仍有工程事实歧义时再向用户确认。

原有排版只作为提取内容和关系的证据，不是必须继承的设计。理解内容后，可以把原表格、文本框或流程图重新组织为卡片、时间轴、矩阵、楼层堆栈、流程或主次分区；但不得改变语义、对应关系、数据口径、施工顺序和主要内容。禁止在未形成语义模型时直接“看图美化”。

默认规则：

- 不删、不改、不臆造用户原文；只拆分层级、换行和重组位置。
- 不改变建筑造型、吊顶、柱网、材质、空间比例和 BIM 模型关系。
- 不编造施工顺序。先核对专业逻辑，再视觉化。
- 每页输出一张独立 2:1 图片，默认 `2000×1000`；不要拼成九宫格或整套长图。
- 只生成表头以下的内容画布。不要生成页面标题栏、页眉、企业名称/Logo、项目名称横幅、章节编号、页码或页脚。
- `title` 只用于理解本页主题和文件命名，不得绘制到图片中，除非用户明确说它属于内容区。
- 若图像工具不能原生输出 2:1，先为裁切保留安全区，再无拉伸地裁切或扩展画布到 2:1；不得压扁、拉宽或裁掉关键内容。

### 2. 基于语义分类，再冻结模板

根据 `semantic_model` 比较页面的内容结构，不比较现有排版。若页面共享主要字段、信息关系和阅读任务，就归为同一 `page_type`。例如同时包含“标段摘要、两个施工区、楼层范围、四类班组、资源矩阵/合计”的页面，统一归为 `construction-zone-allocation`。

采用两阶段自由度：首次为某个 `page_type` 建立模板时，可完全脱离旧排版，按照语义关系选择最合适的信息架构；模板获批并冻结后，同一类型页面的布局自由度归零，只替换数据与声明的状态。不要混淆“可以重构旧版式”和“同类页面可以各自发挥”。

为每个 `page_type` 从 `template-registry.md` 绑定一个固定 `template_id`。同一项目中，相同 `series_key + page_type` 必须使用同一个 `template_id`、组件树、坐标、字号层级、图标语义和辅助色；只允许替换数据、文字、图片与明确声明的空状态。禁止因为楼层数量、字段长短或原页排版不同而另起设计。

若现有模板无法容纳内容，先扩展该模板的确定性容量规则并升级模板版本，再让同类页面全部迁移；不得只为其中一页临时移动组件。对相似页面，布局自由度设为零。

### 3. 冻结风格合同

从 `style-bible.md` 复制固定色板、内容区网格、卡片、图标、圆角、线宽、阴影、摄影语言和禁用项。整个项目只允许改变页面内容与选定版式，不允许改变风格合同。

先为整套项目建立辅助色语义映射，再冻结：工程橙只表示施工阶段/分区，数字青只表示 BIM/数字化，验收绿只表示完成/验收，蓝灰只表示次要信息。每页最多选择一种彩色辅助色；不得为了“丰富”而随机换色。

若用户提供已认可页面，将它设为 `STYLE_ANCHOR`。若没有，先选择最能代表整套内容的一页制作母版样张；通过内容与视觉自检后将其冻结为锚点，再生成其余页面。

### 4. 选择生产模式

默认使用“确定性分层合成模式”：

1. 用图像生成只制作或编辑无文字的场景、设备融合、背景与照片素材。
2. 按固定 `template_id` 的坐标，用同一套 PPT/SVG/HTML/画布组件叠加正文、数字、图标与流程线，不叠加页面表头。
3. 导出页面图片。

该模式是同类页面“完全一致”的默认要求。图像模型不得自由决定同类页面的整体布局。仅当用户明确接受近似一致而非完全一致时，才使用“整页图像模式”；整页图像仍须 OCR/人工核对全部文字。

生成或编辑位图时，同时遵循 `imagegen` Skill。若存在本地源图，始终把源图与固定锚点一起作为参考；不得仅靠文字描述“相同风格”。

### 5. 生成固定母版

先制作一个代表页，检查：

- 中建蓝、白和浅蓝灰占视觉面积 75%–90%；彩色辅助色占 5%–12%，不得超过 15%。
- 强调红固定为 `#E60012`，只标关键数字、日期、风险或核心措施，不与辅助色混用语义。
- 每页最多一种彩色辅助色；蓝灰可作为中性信息色共存。整套同一语义必须使用同一颜色。
- 画布为严格 2:1，内容从画布安全边距内开始；顶部不预制标题栏或页眉。
- 卡片圆角、阴影、描边、内边距、标签高度一致。
- 红色只标关键数字或措施，全套只有这一种红。
- 视觉定位是央企高级工程述标，不是霓虹赛博、互联网仪表盘或普通商务模板。

冻结后不要“再换一种风格”。页面变化通过内容密度和版式模板解决。

### 6. 逐页实例化

每页提示词由三段组成，顺序固定：

1. `STYLE LOCK`：逐字复用，不增删形容词。
2. `SEMANTIC MODEL + PAGE CONTENT`：先写页面目的、实体、关系、阅读顺序，再写原文、图片与专业约束。
3. `TEMPLATE LOCK`：从模板注册表复制固定模板 ID、组件树、坐标和容量规则。

同一 `template_id` 的页面必须由同一渲染器实例化。文本溢出按模板规则处理：先压缩段落间距，再按允许的字号下限缩小，再拆为模板规定的续行；不得移动其他组件或改变卡片尺寸。空数据使用固定空状态，不删除槽位导致其余组件位移。

每次生成都引用同一个 `STYLE_ANCHOR`，必要时同时引用当前页原图。可额外参考上一张合格页来保持节奏，但上一张不能替代固定锚点，避免逐页累积漂移。

设备融合时，只编辑指定局部：真实比例、透视、接触阴影、光向和色温一致；不遮挡主体，不重绘原空间。发现多手、多设备、悬浮或穿模时，局部返工，不重做整页。

### 7. 三重验收

先做内容验收，再做模板一致性验收，最后做风格验收。按 `prompt-contract.md` 的 100 分量表打分。

必须返工的硬失败：

- 未建立语义模型就直接排版，或新排版不能准确表达页面目的、信息关系和阅读顺序。
- 文字减少、错字、错数字或施工逻辑错误。
- 建筑/效果图结构、材质或空间关系改变。
- 出现紫色、粉色、暗红、酒红、大面积黄色或多种红色。
- 中建蓝不再占主导、辅助色面积超过 15%、单页出现多种彩色辅助色，或相同辅助色被随机赋予不同语义。
- 标题位置、卡片半径、图标风格、边距体系明显漂移。
- 相同 `series_key + page_type` 使用不同 `template_id`，或模板指纹、组件坐标、组件顺序不同。
- 人物肢体异常、设备比例错误、穿模、悬浮或光影不一致。
- 多页被合并为一张图。
- 图片不是严格 2:1，或出现表头、标题栏、企业标识、项目横幅、页码、页脚。

总分低于 90 或任一硬失败时，只针对失败项返工。不要借返工机会重新设计其他已合格部分。

## 批量提示词脚本

准备 UTF-8 JSON：

```json
{
  "project_title": "项目技术标述标汇报",
  "style_anchor": "已批准的第 1 页",
  "pages": [
    {
      "page": 1,
      "title": "施工部署 | 竖向施工分区（仅作语义上下文，不渲染）",
      "page_type": "construction-zone-allocation",
      "template_id": "construction-zone-allocation-v1",
      "series_key": "施工区段划分",
      "accent": "orange",
      "semantic_model": {
        "purpose": "说明一标段楼层如何划分为两个施工区并配置独立班组平行施工",
        "entities": ["一标段", "L19-L26", "第一施工区", "第二施工区", "四类班组", "资源数量"],
        "relationships": ["L19-L22 属于第一施工区", "L23-L26 属于第二施工区", "两个施工区平行施工", "各区配置相同类型的独立班组"],
        "reading_order": ["先看标段范围", "再看施工区与楼层对应", "再看班组配置", "最后核对资源数量与合计"]
      },
      "content": ["第1施工区", "第2施工区"],
      "must_preserve": ["建筑比例", "原效果图结构"]
    }
  ]
}
```

运行：

```powershell
python scripts/build_prompts.py brief.json -o prompts.md
```

每页必须填写完整 `semantic_model`，否则脚本拒绝生成，防止在未理解内容时直接套版。优先填写 `page_type`；脚本也会从标题、内容和语义模型推断常见类型。`template_id` 未填写时按注册表自动绑定。相同 `series_key + page_type` 若出现不同模板或辅助色，脚本直接报错。旧字段 `layout` 仍兼容：`cover`、`overview`、`deployment`、`method`、`bim`、`schedule`、`risk`。支持的 `accent`：`none`、`orange`、`teal`、`green`、`slate`。

## 交付

交付时列出页面文件、锚点页面、`page_type`、`template_id`、模板指纹和未能自动验证的内容。逐页图片必须为 2:1 纯内容区，可直接置入用户已有表头下方。若用户需要可编辑 PPT，交付 `.pptx` 与逐页 PNG；不要用纯图片冒充可编辑文件。
