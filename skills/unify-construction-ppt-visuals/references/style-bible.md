# 中建系工程技术标视觉圣经

## 1. 固定视觉令牌

| 类别 | 固定值 |
|---|---|
| 画幅 | 实际内容包围盒严格 `w=2h`，默认 2000×1000；四边各留 60px，最终画布默认 2120×1120，不要求画布 2:1，见 `output-geometry.md` |
| 背景 | 默认真实透明；纯白 `#FFFFFF` 或已确认源配色仅用于内容底板/卡片内部；框外不得有底色或纹理 |
| 深蓝 | `#005BAC` |
| 标准蓝 | `#0068D9` |
| 浅蓝 | `#EAF4FF` |
| 浅冷灰 | `#F3F6F9`；用于卡片内部、零值单元格和非数据承载面，不得铺入透明外围留白 |
| 分隔灰 | `#DCE3EA`；用于中性分隔、细描边和低对比层次，不表示业务状态 |
| 强调红 | `#E60012`，全套唯一红色 |
| 工程橙 | `#F59E0B` / 浅色 `#FFF4D6`；施工阶段、分区、机械 |
| 数字青 | `#0F9FA8` / 浅色 `#E6F7F7`；BIM、数字化、信息系统 |
| 验收绿 | `#2E9B65` / 浅色 `#EAF7F0`；完成、验收、达标 |
| 蓝灰 | `#64748B` / 浅色 `#F1F5F9`；次要信息、中性状态 |
| 正文 | 深蓝灰，不用纯黑大标题 |
| 图标/缩略图 | 抽象语义使用同一套蓝色线性图标；材料、设备和构配件可使用统一光影的写实小图；同层级统一模式、视觉尺寸、容器与位置 |
| 卡片 | 轻圆角；白、浅冷灰、浅蓝或当前登记的辅助浅色按层级选用；细浅蓝或分隔灰描边；极轻中性阴影 |
| 标签 | 标准蓝底或浅蓝底；同层级同高度 |
| 摄影 | 写实、自然中性光、工程现场真实质感 |
| 装饰 | 只能放在卡片内部并裁切于卡片边界；允许低对比纹理、浅色填充、细线或坐标点，不得污染画布底层 |

推荐比例令牌：外围四边使用同一个整数像素边距 `m`，默认取实际内容包围盒宽度 3%，上下也使用该像素值；卡片间距约宽度 1.2%，主内容区占安全框 100%。最终几何与模板适配以 [output-geometry.md](output-geometry.md) 为准。所有一级内容框架统一使用像素左边界 `left=m`、右边界 `right=m+w`；框架上下排列时必须形成贯通整页的两条竖向对齐线。顶部与底部都不预留或生成表头、页眉、标题栏、企业标识、项目横幅、页码、页脚。同一套页面只使用一组比例。

### 画布与卡片纹理边界

- 画布最底层默认透明，包括无底板的卡片间隙、四周安全边距和框架外围留白；纯白或已确认颜色只用于内容底板和卡片内部。
- 禁止在画布底层添加浅蓝渐变、建筑线稿、蓝图网格、坐标刻度、噪点、纸张纹理、光斑或水印。
- 卡片内部可以使用浅蓝、浅橙、浅青、浅绿或蓝灰填充，也可以使用低对比工程线稿、网格或材质纹理；必须受卡片蒙版裁切，不得穿透圆角或跨到相邻卡片及页面留白。
- 顶层框架本身默认白底或透明；若使用框架底板，仍须保持纯色，不得把纹理铺满整组框架。

### 一级框架竖向对齐

- 把页面的顶层内容带、主要分区框和路线图区视为 `PrimaryFrame`。所有 `PrimaryFrame` 共用相同左、右边界，使用 `left=m`、`right=m+w`（默认 60px、2060px）。
- 对齐对象固定为每个 `PrimaryFrame` 最外层“可见描边的直线段”。圆角端点、阴影、内部留白、标题文字和内部卡片均不得替代外边框作为测量基准。
- 上下两个框架即使内部列数不同，也必须让外框左边缘、右边缘分别落在同一条竖线上；禁止顶部缩进、中部外扩或底部越界。
- 内部卡片遵循固定列网格。每一行的首张卡左边缘对齐全局左边界，末张卡右边缘对齐全局右边界；列间距统一。
- 输出后记录全部一级框架的 `left_px` 与 `right_px`。默认 2000px 宽实际内容区域的同侧边界目标值必须相同，最大允许测量误差为 2px；其他宽度按比例换算。超过容差不得以“视觉上接近”为由通过验收，必须定向返工外框边界。
- 只有用户明确指定悬浮边注、出血图片或超宽关系箭头时才允许越过全局边界，并须在语义账本中声明例外。

这些是项目级视觉令牌，不等于页面模板。相同内容模式还必须使用 `template-registry.md` 中同一模板的精确坐标；旧百分比坐标仅作首次适配基准，不得继续作为最终画布外围边距或逐页漂移的许可。

导出按 `output-geometry.md` 同时验收实际内容包围盒 `w=2h` 与四边等像素透明留白，最终画布宽高比不强求 2:1。末端裁边/补边不得损伤内容；无法同时满足时用 ImageGen 重排主体，不得非等比拉伸或单向大量补边。内部框架对齐的 2px 容差不适用于最终比例和透明边距。

### 配色占比与使用规则

- 不再要求冷暖混搭，也不再默认加入暖象牙、暖灰或暖色表面。先判断页面属于 `source-led`、`expanded-auxiliary` 还是 `labor-cool-lock`，再执行对应合同。
- `source-led`：只要源页、源图、效果图、照片、图表或原有界面存在明确且有意图的色板，先提炼核心语义色，再沿用并强化。与主要实体、分区、状态直接绑定的颜色不受色相、冷暖或面积限制；紫、粉、黄、橙、绿、褐等颜色不得仅因通用禁用色规则而被改蓝或降饱和。纯装饰色、重复强调色和与一级语义竞争的噪声色可以删除、合并或重映射，但必须记录原色、去向和理由。新增界面元素优先从核心语义色取色。
- `expanded-auxiliary`：当源内容近乎白蓝灰或其他单一色调、没有明确可沿用色板时，建立 2–4 种协调辅助色，合计覆盖可见面积至少 20%。颜色优先承担分点编号/项目符号、关键词标签、因果节点与箭头、关系分组与连线、流程阶段、并列模块和数据类别；不得只靠细描边、小图标或零散装饰点凑面积。
- `expanded-auxiliary` 不再受“一种主色 + 一种微色”、6%–10%、3% 或 12% 的旧上限约束。可在专业、清晰、可区分的前提下发散色相，但每种颜色必须登记稳定语义，避免无意义彩条和随机棋盘格。
- `labor-cool-lock`：劳动力计划与工种投入矩阵沿用现有白色、中建蓝、浅冷灰和唯一峰值红，不应用 20% 辅助色扩展，不增加暖色补色，并保持 `labor-workforce-plan-v1.png` 的初始版式与几何。
- 中建蓝继续控制本次新增的关键层级、标题、数据主线和重复语义，但除 `labor-cool-lock` 外不再设统一面积目标或 30% 通用硬上限；是否占主导取决于源色板和页面语义。
- 源照片、材料、设备和效果图一律保留真实颜色。`source-led` 模式下这些颜色直接构成页面色板且不限制面积；`expanded-auxiliary` 模式不得给它们统一套蓝色或暖色滤镜，也不得虚构图片来凑颜色比例。
- 本次新增的文字强调红 `#E60012` 不属于辅助色，只表示关键数字、日期、风险、关键动作、关键词组或核心措施，通常控制在 3% 以内且不是必须达到的目标。新增标红内容必须逐字来自原文并预先登记到 `critical_phrases`；每页优先 1–3 处，禁止整句整段铺红。源图或原有图表中本来存在的红色按 `source-led` 保留，不受这条新增强调规则限制。
- 连续句子中的非数字关键词允许并推荐标红。选取对象应是能够独立表达管理重点的完整原文短语，例如施工方法、控制动作、关键对象、约束或结果；只改变该短语字符颜色，句中其他文字、空格和标点保持正文色。
- 先按语义选色，再按整套复用。每页在内容账本登记 `palette_mode`、`source_palette`、`auxiliary_palette`、`auxiliary_ratio` 和 `color_role_map`；禁止同一新增语义跨页换色，也禁止同一种新增颜色一会儿表示完成、一会儿表示风险。
- `expanded-auxiliary` 页面不能以“没有明确语义”为由退回单一蓝灰；应从已有分点、因果、关系、流程、阶段或类别中建立真实可区分的颜色角色。
- 大胆不等于颜色种类多，而是让少数核心语义色形成足够大的视觉质量。至少建立“大型区域蒙层/底板 + 中型标题条/徽章/行底 + 小型文字/箭头/节点”三个尺度；当页面有可分区的建筑、模型或照片时，优先用 8%–20% 透明度的整块蒙层直接覆盖对应实体区域。
- 同一实体跨多个视觉区域出现时必须建立 `cross_region_color_map`。例如同一施工区的建筑蒙层、施工区标签、竖向箭头、楼层徽章、日期行底和日期强调必须使用同一色系，使读者无需图例即可完成对应。
- 原照片可在保持建筑事实和关键细节可辨的前提下适度降对比、压低饱和或覆盖半透明语义色，使信息标注成为第一视觉层；这属于信息层级处理，不等于改变建筑材质或结构。
- 避免连续三个以上一级模块全部使用同一种浅蓝底。优先按信息分组和关系使用白、浅冷灰、浅蓝与已登记辅助浅色，不做无意义的棋盘格交替。

推荐颜色角色（用于 `expanded-auxiliary` 的 2–4 色组合之一，不表示整页只能使用该色）：

| 页面/内容 | 默认辅助色 |
|---|---|
| 施工部署、施工分区、机械设备 | 工程橙 |
| 专项方案、施工流程 | 工程橙或蓝灰，二选一 |
| BIM、智慧工地、数字平台 | 数字青 |
| 验收、交付、完成状态、质量达标 | 验收绿 |
| 项目概况、工期计划、通用信息 | 蓝灰或不使用 |
| 劳动力计划、工种投入矩阵 | `labor-cool-lock`；中建蓝呈现趋势与热力强度，浅冷灰/近白中性灰承载零值和非数据表面，唯一红只标峰值；保持初始版式 |
| 风险与关键日期 | 仍使用唯一强调红，不新加风险色 |

## 2. 视觉身份

固定关键词：央企高端工程述标、现代、专业、数字化、精装品质、克制科技感、真实施工语境。

不属于该身份：霓虹赛博朋克、紫蓝渐变 SaaS 仪表盘、玻璃拟态、卡通插画、杂志拼贴、奢华金黑、红色政务展板、普通 Word 表格截图。

## 3. 页面槽位

以下槽位只用于首次分类。确定页面类型后，必须转入 `template-registry.md` 的固定模板；相似页面不得继续自由解释槽位。

### cover

仅生成封面所需的项目建筑主视觉内容，不生成企业标识、项目名称、汇报类型或任何表头文字；这些由用户自己的表头承载。

### overview

左侧统一宽度的字段标签；右侧内容边界完全对齐。大数字可做 2–4 个数据卡。文字很多时拆成“关键词 + 原文说明”，不删内容。内容直接从安全框顶部开始，不设置页面标题栏。

### deployment

左侧施工区域；中部真实三维模型/效果图；右侧文字说明；底部施工逻辑。分区色从模型/建筑区域延伸到对应标签、箭头、说明卡、日期行和数据状态，形成跨区域映射；允许使用大面积半透明蒙层、实色标题条和浅色行底，不得把分区色限制在模型上的几根描边。

### method

上部质量控制要点；左侧流程；右侧现场照片卡；底部固定控制主线。施工顺序必须先核实。照片卡使用相同宽高比、圆角与标签。

### bim

主视觉为 BIM 模型或应用场景，而非裸软件截图；一侧解释应用，底部总结管理价值。界面截图置于统一设备框或卡片内。源界面有明确配色时保留模型和界面的真实颜色身份，同时提炼与系统、数据路径和状态直接绑定的核心语义色；装饰噪声可登记后删并或重映射。无明确配色时数字青作为数字系统主角色，并与另外 1–3 种协调辅助色共同达到至少 20% 的可见面积。

### schedule

先读取 `gantt-layout-system.md` 判定行语义。连续工序使用阶段/依赖语法；楼栋、区域、设备等并列对象使用平行甘特条，不得用箭头串成工序链；离散里程碑使用月份/季度节点矩阵。优先采用“左侧精简字段表 + 右侧精确时间轴”的主骨架，侧边重点、阶段摘要、当前进度线、负责人和底部统计带仅在源页有对应内容时出现。重点日期/天数用唯一强调红，不同时使用多种红色层级。

甘特图不沿用参考模板的纯蓝限制。源页已有明确条带或对象色时使用 `source-led` 并建立跨表格、时间轴和地图的同色映射；源页近乎单色时使用 `expanded-auxiliary`，以 2–4 种协调色承担对象、专业、区域、阶段或状态，主要落在条带、对象标签、侧卡和分组底板上，合计可见面积至少 20%。中建蓝继续控制年份、季度、月份表头与关键框架。

### risk

风险、措施、责任与结果形成明确映射。优先采用横向四列或闭环流程，不用大量警示色块。

### risk-analysis-measures-series

用于同一章节内持续出现“分析 → 措施”阅读主线的重难点、风险、污染物控制和供货保障页面。即使有的页面是一张大图、有的是四张卡、有的是前后对比，只要阅读任务相同就必须视为同系列。

- `AnalysisHeader`：固定显示“分析”，使用 `measure` 线性图标、中建蓝图标底板和统一字体/字号/坐标。
- `MeasuresHeader`：固定显示“措施”，使用 `plan` 线性图标、中建蓝字体与固定工程橙短线微标识；字体、字号、图标底板和坐标不得跨页变化。
- “分析”和“措施”是同一层级标签：两者必须使用完全相同的字体家族和字号，默认字重也相同。该要求同时适用于单页内横向比较和系列跨页比较；不得把任一标签缩小、放大或换字体。
- 两个标题组件始终存在。连续页也必须用该页原文填入分析槽位，不得因原页没有独立标题框而省略。
- 页面照片和文字量的变化只在固定 `ContentBody` 内选择登记过的密度状态；不得把密度差异当成重新设计标题区的理由。

### labor-workforce-plan

默认使用 `labor-workforce-plan-v1`：顶部管理结论与峰值卡，中部月度合计趋势，下部工种投入热力矩阵。该类页面强制 `labor-cool-lock`，不添加装饰性图标，也不执行普通页面至少 20% 的辅助色扩展；峰值卡、折线峰值和合计行峰值必须是同一个精确值。折线与热力矩阵共享中建蓝尺度，零值和非数据表面使用浅冷灰 `#F3F6F9` 或近白中性灰，红色只标峰值。严格保持 `assets/templates/labor-workforce-plan-v1.png` 的初始组件顺序、几何和阅读路径，不把整页改成互联网数据大屏，也不得让浅蓝铺满所有留白。

### construction-zone-floor-schedule

使用 `construction-zone-floor-schedule-v1`。左侧保留建筑/楼层立面作为事实底图，按施工区施加大面积半透明语义蒙层；右侧把逐层日期重组为等高行卡，施工区颜色同步用于楼层徽章、行底、日期强调和组间分隔；顶部用轻量结论引导，底部用跨页宽度的结论条闭合阅读。以 [美化后参考图](../assets/references/construction-zone-floor-schedule-after.png) 为类型级锚点，[原图](../assets/references/construction-zone-floor-schedule-before.png) 只作对照。

该参考的关键不是“蓝色 + 红色”本身，而是以下视觉因果：

- 从原图的蓝、红、黄中提炼蓝/红为两个施工区的核心语义色；黄色时长箭头被合并到所属分区色，减少第三套竞争语法。
- 蓝/红不只出现在边框，而是分别覆盖建筑上下分区，并同步复制到箭头、标签、楼层徽章、日期行和关键日期，形成无需图例的闭环。
- 建筑照片被适度压低对比，分区蒙层与白色标注成为主层；建筑结构仍清晰可辨。
- 原来散落的垂直大字、黑色虚线、黄色回转箭头和裸文本被收拢为两张统一卡片、等高行列和一致的圆角/阴影系统。
- “大胆”来自大色块和稳定重复，不来自增加更多颜色、提高所有元素饱和度或堆叠装饰。

## 4. 图片规则

- 原项目效果图是事实源，不是灵感图。保留视角、结构、材质、空间关系和主体。
- 图片裁切遵循主体安全区；不得把关键建筑、设备或人员截断。
- 多张照片统一色温、曝光、对比度、圆角、标签和宽高比。
- 施工设备融合须满足透视、比例、落地点、接触阴影、遮挡关系和光向一致。
- 人物以真实工程人员为主；避免摆拍、夸张姿势、重复面孔和肢体异常。

## 5. 文字规则

- 保留所有原文与数字。允许分段、换行、分类、变成流程或卡片，但不得概括替代原文。
- 红色只用于少量关键数字、日期、节点、原文关键字/词组、关键动作或核心措施。先登记 `critical_phrases`，再逐字标红；不局限于数字，也不允许整段变红。
- `critical_phrases` 必须按原文的连续字符登记，优先为 2–12 个汉字的完整词组。禁止拆词标红、把近义改写当作原文、仅标“加强”“做好”等无独立信息量的泛词，或让相邻标红片段连成整句。
- 不用彩色 emoji 代替图标。
- 内容区小标题、正文、注释三级层级固定，不在单页临时发明字号体系。页面标题只作语义上下文，不渲染。

## 6. 图标与写实缩略图硬规则

- 三个及以上重复模块/阶段、设备措施清单、材料/构配件清单、施工区/楼层/班组映射必须使用视觉标识；不得整页省略。
- `icon_plan` 必须先选择模式：`semantic-line` 用于流程、阶段、组织、区域、楼层、班组、风险和管理概念；`realistic-thumbnail` 用于材料、设备、样品、构配件和产品类别。
- `semantic-line` 默认使用 `assets/icons/construction-line-icons.svg`，采用 24×24 视框、圆角端点、1.8px 等效线宽；常规颜色为中建蓝，施工分区/机械允许工程橙，完成/验收允许验收绿。
- `realistic-thumbnail` 使用单一物体或小型组合的写实抠图：白色、浅冷灰或透明感背景、统一约 3/4 视角、自然中性棚拍光、柔和接触阴影、无文字、无商标、无水印、无虚构品牌。物体自身的自然材料颜色必须完整保留；界面层只提炼与类别、状态和关系绑定的核心语义色，禁止统一染蓝或强行暖化。
- 写实缩略图固定在同尺寸的 1:1 或近方形容器中，主体占容器 68%–82%；同一系列的机位、比例、光向、阴影强度和裁切必须一致，禁止有的俯视、有的正视、有的卡通渲染。
- 同一层级只允许一种模式。栏目标题可使用线性图标、条目卡可同时使用写实缩略图，因为二者角色不同；不得在同一组条目卡中混用线性图标、卡通贴纸、3D 玩具渲染和写实照片。
- 每个主要模块只放一个主要标识，标识用于识别语义，不作为装饰填空，不替代名称或精确数字。完整模式判定与例外见 `icon-system.md`。
- 连续正文、精确矩阵或确实没有稳定隐喻时可以不用标识，但必须在语义账本中声明 `icon_plan: none` 及原因。
