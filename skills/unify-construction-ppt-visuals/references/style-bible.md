# 中建系工程技术标视觉圣经

## 1. 固定视觉令牌

| 类别 | 固定值 |
|---|---|
| 画幅 | 严格 2:1，默认 2000×1000 |
| 背景 | 纯白色 `#FFFFFF`，不得使用渐变、蓝图线稿、网格、水印或其他纹理 |
| 深蓝 | `#005BAC` |
| 标准蓝 | `#0068D9` |
| 浅蓝 | `#EAF4FF` |
| 暖象牙 | `#F7F4EE`；只用于卡片内部、零值单元格和非数据承载面，不得替代纯白画布 |
| 暖灰 | `#E8E2D8`；只用于中性分隔、细描边和低对比层次，不表示业务状态 |
| 强调红 | `#E60012`，全套唯一红色 |
| 工程橙 | `#F59E0B` / 浅色 `#FFF4D6`；施工阶段、分区、机械 |
| 数字青 | `#0F9FA8` / 浅色 `#E6F7F7`；BIM、数字化、信息系统 |
| 验收绿 | `#2E9B65` / 浅色 `#EAF7F0`；完成、验收、达标 |
| 蓝灰 | `#64748B` / 浅色 `#F1F5F9`；次要信息、中性状态 |
| 正文 | 深蓝灰，不用纯黑大标题 |
| 图标/缩略图 | 抽象语义使用同一套蓝色线性图标；材料、设备和构配件可使用统一光影的写实小图；同层级统一模式、视觉尺寸、容器与位置 |
| 卡片 | 轻圆角；白、暖象牙、浅蓝按层级选用；细浅蓝或暖灰描边；极轻中性阴影 |
| 标签 | 标准蓝底或浅蓝底；同层级同高度 |
| 摄影 | 写实、自然中性光、工程现场真实质感 |
| 装饰 | 只能放在卡片内部并裁切于卡片边界；允许低对比纹理、浅色填充、细线或坐标点，不得污染画布底层 |

推荐比例令牌：内容画布安全边距约宽度 3%，卡片间距约 1.2%，主内容区占安全框 100%。所有一级内容框架统一使用左边界 `x=3%`、右边界 `x=97%`；框架上下排列时必须形成贯通整页的两条竖向对齐线。顶部与底部都不预留或生成表头、页眉、标题栏、企业标识、项目横幅、页码、页脚。同一套页面只使用一组比例。

### 画布与卡片纹理边界

- 画布最底层必须是纯白色 `#FFFFFF`，包括卡片之间的间隙、四周安全边距和框架外围留白。
- 禁止在画布底层添加浅蓝渐变、建筑线稿、蓝图网格、坐标刻度、噪点、纸张纹理、光斑或水印。
- 卡片内部可以使用浅蓝、浅橙、浅青、浅绿或蓝灰填充，也可以使用低对比工程线稿、网格或材质纹理；必须受卡片蒙版裁切，不得穿透圆角或跨到相邻卡片及页面留白。
- 顶层框架本身默认白底或透明；若使用框架底板，仍须保持纯色，不得把纹理铺满整组框架。

### 一级框架竖向对齐

- 把页面的顶层内容带、主要分区框和路线图区视为 `PrimaryFrame`。所有 `PrimaryFrame` 共用相同左、右边界，默认 `x=3%`、`w=94%`。
- 对齐对象固定为每个 `PrimaryFrame` 最外层“可见描边的直线段”。圆角端点、阴影、内部留白、标题文字和内部卡片均不得替代外边框作为测量基准。
- 上下两个框架即使内部列数不同，也必须让外框左边缘、右边缘分别落在同一条竖线上；禁止顶部缩进、中部外扩或底部越界。
- 内部卡片遵循固定列网格。每一行的首张卡左边缘对齐全局左边界，末张卡右边缘对齐全局右边界；列间距统一。
- 输出后记录全部一级框架的 `left_px` 与 `right_px`。默认 2000px 宽画布的同侧边界目标值必须相同，最大允许测量误差为 2px；其他宽度按比例换算。超过容差不得以“视觉上接近”为由通过验收，必须定向返工外框边界。
- 只有用户明确指定悬浮边注、出血图片或超宽关系箭头时才允许越过全局边界，并须在语义账本中声明例外。

这些是项目级视觉令牌，不等于页面模板。相同内容模式还必须使用 `template-registry.md` 中同一模板的精确坐标；不得把“约 3%”当作允许逐页漂移的区间。

若生成工具不支持原生 2:1，把关键内容限制在中央安全区，随后通过裁切或补边得到 2:1。保持原始比例，不进行非等比缩放。

### 配色占比与使用规则

- 纯白与浅中性色（白、暖象牙、浅蓝灰、暖灰）目标占视觉面积 55%–68%。画布底层仍必须是纯白；暖象牙和暖灰只能用于卡片内部、零值单元格、分隔和非数据承载面。
- 当页面同时满足 `accent: none`、`micro_accent: none`、没有源照片/材料/设备，且属于劳动力矩阵、计划表、统计表等分析型数据页时，不得为了凑色额外引入业务色；此时纯白与浅中性色可自然放宽到 68%–82%，仍须保持中建蓝 18%–25% 的目标区间和 30% 的硬上限。
- 中建蓝色系目标占视觉面积 18%–25%，复杂数据页可放宽但不得超过 30%。其中深蓝与标准蓝等高饱和蓝合计宜控制在 8%–15%，其余用浅蓝完成层级。品牌主导来自关键层级、标题、数据主线和重复语义的一致性，不等于把每个表面都染蓝。
- 每页允许一种主语义辅助色，目标占 6%–10%、硬上限 10%；仅用于有来源依据的小标签、节点、细线、图标局部、数字底片或模型分区。
- 当页面确有第二个需要区分的语义状态时，可登记一种不同色相的 `micro_accent`，面积不得超过 3%；主辅助色与微辅助色合计不得超过 12%。没有第二语义时必须使用 `micro_accent: none`，不得为了“更丰富”增加颜色。
- 照片、材料、设备和效果图中原本存在的自然色不计入 UI 辅助色。页面含这些源图时，优先让其自然色占约 8%–18% 以形成真实冷暖层次；页面没有源图时不得为了配色占比虚构照片或材料，可改用 8%–15% 的暖中性卡片表面补足温度层次。
- 强调红 `#E60012` 不属于辅助色，只表示关键数字、日期、风险、关键动作、关键词组或核心措施，通常控制在 3% 以内且不是必须达到的目标。标红内容必须逐字来自原文并预先登记到 `critical_phrases`；每页优先 1–3 处，禁止整句整段铺红。
- 连续句子中的非数字关键词允许并推荐标红。选取对象应是能够独立表达管理重点的完整原文短语，例如施工方法、控制动作、关键对象、约束或结果；只改变该短语字符颜色，句中其他文字、空格和标点保持正文色。
- 先按语义选色，再按整套复用。每页在内容账本登记 `accent`、`micro_accent`、自然色来源和暖中性表面用途；禁止同一语义跨页换色，也禁止同一种颜色一会儿表示完成、一会儿表示风险。
- 没有明确语义时使用 `none` 或蓝灰，不要强行增加颜色。
- 避免连续三个以上一级模块全部使用同一种浅蓝底。优先用白、暖象牙和浅蓝按信息层级分配表面，不做无意义的棋盘格交替。

推荐映射：

| 页面/内容 | 默认辅助色 |
|---|---|
| 施工部署、施工分区、机械设备 | 工程橙 |
| 专项方案、施工流程 | 工程橙或蓝灰，二选一 |
| BIM、智慧工地、数字平台 | 数字青 |
| 验收、交付、完成状态、质量达标 | 验收绿 |
| 项目概况、工期计划、通用信息 | 蓝灰或不使用 |
| 劳动力计划、工种投入矩阵 | 主、微辅助色均为 `none`；中建蓝呈现趋势与热力强度，暖象牙/中性灰承载零值和非数据表面，唯一红只标峰值 |
| 风险与关键日期 | 仍使用唯一强调红，不新加风险色 |

## 2. 视觉身份

固定关键词：央企高端工程述标、现代、专业、数字化、精装品质、克制科技感、真实施工语境。

不属于该身份：霓虹赛博朋克、紫蓝渐变 SaaS 仪表盘、玻璃拟态、卡通插画、杂志拼贴、奢华金黑、红色政务展板、普通 Word 表格截图。

## 3. 页面槽位

以下槽位只用于首次分类。确定页面类型后，必须转入 `template-registry.md` 的固定模板；相似页面不得继续自由解释槽位。

### cover

仅生成封面所需的项目建筑主视觉内容，不生成企业标识、项目名称、汇报类型或任何表头文字；这些由用户自己的表头承载。

### overview

左侧统一宽度的字段标签；右侧内容边界完全对齐。大数字可做 2–4 个数据卡。文字很多时拆成“关键词 + 原文说明”，不删内容。内容直接从安全框顶部开始，不设置页面标题栏。

### deployment

左侧施工区域；中部真实三维模型/效果图；右侧文字说明；底部施工逻辑。分区色默认中建蓝与工程橙，仅用于模型区域标识，不扩展为整页主色。

### method

上部质量控制要点；左侧流程；右侧现场照片卡；底部固定控制主线。施工顺序必须先核实。照片卡使用相同宽高比、圆角与标签。

### bim

主视觉为 BIM 模型或应用场景，而非裸软件截图；一侧解释应用，底部总结管理价值。界面截图置于统一设备框或卡片内，可使用数字青作为唯一彩色辅助色。

### schedule

用同一基线的时间轴、里程碑或阶段卡。重点日期/天数用唯一强调红，不同时使用多种红色层级。

### risk

风险、措施、责任与结果形成明确映射。优先采用横向四列或闭环流程，不用大量警示色块。

### risk-analysis-measures-series

用于同一章节内持续出现“分析 → 措施”阅读主线的重难点、风险、污染物控制和供货保障页面。即使有的页面是一张大图、有的是四张卡、有的是前后对比，只要阅读任务相同就必须视为同系列。

- `AnalysisHeader`：固定显示“分析”，使用 `measure` 线性图标、中建蓝图标底板和统一字体/字号/坐标。
- `MeasuresHeader`：固定显示“措施”，使用 `plan` 线性图标、中建蓝字体与固定工程橙短线微标识；字体、字号、图标底板和坐标不得跨页变化。
- “分析”和“措施”是同一层级标签：两者必须使用完全相同的字体家族和字号，默认字重也相同。该要求同时适用于单页内横向比较和系列跨页比较；不得把任一标签缩小、放大或换字体。
- 两个标题组件始终存在。连续页也必须用该页原文填入分析槽位，不得因原页没有独立标题框而省略。
- 页面照片和文字量的变化只在固定 `ContentBody` 内选择登记过的密度状态；不得把密度差异当成重新设计标题区的理由。

### labor-workforce-plan

默认使用 `labor-workforce-plan-v1`：顶部管理结论与峰值卡，中部月度合计趋势，下部工种投入热力矩阵。该类页面强调数据分析，不添加装饰性图标；峰值卡、折线峰值和合计行峰值必须是同一个精确值。折线与热力矩阵共享中建蓝尺度，零值和非数据表面优先使用暖象牙或近白中性灰，红色只标峰值，不把整页做成互联网数据大屏，也不得让浅蓝铺满所有留白。

## 4. 图片规则

- 原项目效果图是事实源，不是灵感图。保留视角、结构、材质、空间关系和主体。
- 图片裁切遵循主体安全区；不得把关键建筑、设备或人员截断。
- 多张照片统一色温、曝光、对比度、圆角、标签和宽高比。
- 施工设备融合须满足透视、比例、落地点、接触阴影、遮挡关系和光向一致。
- 人物以真实工程人员为主；避免摆拍、夸张姿势、重复面孔和肢体异常。

## 5. 文字规则

- 保留所有原文与数字。允许分段、换行、分类、变成流程或卡片，但不得概括替代原文。
- 红色只用于少量关键数字、日期、节点、原文关键字/词组、关键动作或核心措施。先登记 `critical_phrases`，再逐字标红；不局限于数字，也不允许整段变红。
- `critical_phrases` 必须按原文的连续字符登记，优先为 2–12 个汉字的完整词组。禁止拆词标红、把近义改写当作原文、仅标“加强”“做好”等无独立信息量的泛词，或让相邻标红片段连成整句。
- 不用彩色 emoji 代替图标。
- 内容区小标题、正文、注释三级层级固定，不在单页临时发明字号体系。页面标题只作语义上下文，不渲染。

## 6. 图标与写实缩略图硬规则

- 三个及以上重复模块/阶段、设备措施清单、材料/构配件清单、施工区/楼层/班组映射必须使用视觉标识；不得整页省略。
- `icon_plan` 必须先选择模式：`semantic-line` 用于流程、阶段、组织、区域、楼层、班组、风险和管理概念；`realistic-thumbnail` 用于材料、设备、样品、构配件和产品类别。
- `semantic-line` 默认使用 `assets/icons/construction-line-icons.svg`，采用 24×24 视框、圆角端点、1.8px 等效线宽；常规颜色为中建蓝，施工分区/机械允许工程橙，完成/验收允许验收绿。
- `realistic-thumbnail` 使用单一物体或小型组合的写实抠图：白色、暖象牙或透明感背景、统一约 3/4 视角、自然中性棚拍光、柔和接触阴影、无文字、无商标、无水印、无虚构品牌。自然材料颜色不计入界面辅助色数量，并在有真实来源时承担页面冷暖平衡，禁止统一染蓝。
- 写实缩略图固定在同尺寸的 1:1 或近方形容器中，主体占容器 68%–82%；同一系列的机位、比例、光向、阴影强度和裁切必须一致，禁止有的俯视、有的正视、有的卡通渲染。
- 同一层级只允许一种模式。栏目标题可使用线性图标、条目卡可同时使用写实缩略图，因为二者角色不同；不得在同一组条目卡中混用线性图标、卡通贴纸、3D 玩具渲染和写实照片。
- 每个主要模块只放一个主要标识，标识用于识别语义，不作为装饰填空，不替代名称或精确数字。完整模式判定与例外见 `icon-system.md`。
- 连续正文、精确矩阵或确实没有稳定隐喻时可以不用标识，但必须在语义账本中声明 `icon_plan: none` 及原因。

## 7. 禁用清单

紫色、粉色、暗红、酒红、大面积黄色、未经定义的新色、辅助色大面积铺底、未登记的第二彩色辅助色、`micro_accent` 超过 3%、主辅助色与微辅助色合计超过 12%、中建蓝色系超过 30%、连续大面积浅蓝铺底、把自然照片或材料统一染蓝、跨页随机换色、整句整段标红、卡片外的任何纹理或渐变、画布底层蓝图线稿/网格/水印、一级框架左右边界错位、彩色 emoji、同层级混用线性/卡通/3D/写实标识、写实缩略图带品牌或文字、厚重投影、强玻璃拟态、霓虹光、过度发光边框、随机圆角、不同图标库混用、页面表头、标题栏、企业标识、项目横幅、页码、页脚、漂浮居中大标题、无对齐依据的装饰、改变原图空间、自动补写施工事实。
